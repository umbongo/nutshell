# Telnet Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A third session type, Telnet, with passive option negotiation, auto-login at recognised login and password prompts, a password prompt box (also used by SSH password-auth profiles with no saved password), plain-spoken connect status lines for port checks, and the AI panel running commands on it as on SSH.

**Architecture:** Everything that can be pure is in `src/core/` with native tests: the protocol (`telnet_proto`: IAC parsing across `recv` boundaries, passive negotiation, NAWS, TTYPE, outgoing escaping and CR to CR LF), the login matcher (`telnet_login`), the status lines and connect-outcome merge (`telnet_status`), and a transport-free session engine (`telnet_session`) that drives a real `Terminal` and owns local echo, the matcher, the credentials and the outgoing queue. `src/ui/telnet_io.c` is thin socket glue: a blocking connect for the worker thread and a non-blocking `SessionIo` (`SESSION_TELNET`). `window.c` branches on the profile kind at the connect thread, `WM_CONN_DONE`, the EOF path and reconnect, and shows the password box on the UI thread (telnet) or through `conn_prompt` (SSH).

**Tech Stack:** C11, Win32/Winsock2 cross-compiled with `x86_64-w64-mingw32-gcc`, native tests through `make test` (`tests/test_framework.h`, `tests/runner.c`), Win32 tests through `make wintest` (`tests/win_runner.c`), PowerShell 5.1 integration harness (`tests/integration/`), design-system modules.

**Spec:** `docs/superpowers/specs/2026-11-03-telnet-and-password-reveal-design.md` (approved 2026-11-03), everything except "Hold-to-reveal" on the three existing fields, which is `docs/superpowers/plans/2026-11-03-password-reveal.md` (pull request 1). **This branch is cut from `main` after pull request 1 merges**; it consumes, by name: `HWND pw_reveal_attach(HWND edit)`, `void pw_reveal_mask_all(HWND root)` (`src/ui/pw_reveal.h`), and `PwPromptOpts` / `int pw_prompt_show(HWND parent, const PwPromptOpts *opts, char *out, int out_size)` (`src/ui/pw_prompt.h`), which Task 8 extends.

## Global Constraints

Copied from the spec; every task includes them.

- "`Profile.kind` gains the value `"telnet"`"; the profile editor shows "host, port, username, password and platform, and hides key path, auth type and shell. Choosing Telnet sets the port to 23 when the port field still holds SSH's 22 (and back)." Port default 23.
- The telnet password "is stored exactly like an SSH profile password (DPAPI, `$dpapi$v1$`, preserved verbatim on another PC/user)."
- "`SessionKind` gains `SESSION_TELNET`." Telnet "takes the **remote-host** path wherever SSH and local differ for the AI panel and dispatch", and "is excluded from SSH-only machinery (libssh2 keepalive, host key checks, SFTP, `io.kind == SESSION_SSH` gates)."
- "Telnet is a third backend behind the existing `SessionIo` interface; SSH and ConPTY paths do not change behaviour." "Telnet's `poll` and `write` must therefore never block: non-blocking socket, connect on a worker thread as SSH's `connection_thread` does."
- Negotiation: "RFC 854/855 with loop protection (RFC 1143 style: never answer a request that would not change state)." "**Passive: Nutshell never starts a negotiation, it only answers**." "server `WILL ECHO` → `DO ECHO`; server `WILL SUPPRESS-GO-AHEAD` → `DO SUPPRESS-GO-AHEAD`; server `DO SUPPRESS-GO-AHEAD` → `WILL SUPPRESS-GO-AHEAD`. `DO NAWS` → `WILL NAWS`, then send the window size, and send it again on every terminal resize. `DO TERMINAL-TYPE` → `WILL TERMINAL-TYPE` and answer `SEND` with `XTERM`. Refuse every other option (`WONT`/`DONT`)."
- Local echo: "until the server has agreed to echo (`WILL ECHO`), Nutshell echoes what the user types"; "Once the server echoes, local echo stops; if the server withdraws (`WONT ECHO`), it resumes." "suppressed while a password prompt is on screen (the matcher's password-prompt test on the cursor line)". "The auto-sent password and the password box's value bypass local echo always. Keys are sent as they are typed either way (no line buffering)."
- "Outgoing `0xFF` bytes are doubled (`IAC IAC`)." "the telnet backend's `write` turns a lone CR into CR LF". "Incoming `IAC` sequences are stripped before bytes reach the terminal parser; a sequence split across two `recv` calls is handled."
- Auto-login "Armed when the profile has a username **or** a saved password"; matcher on "the text at the cursor's line once output pauses ... case-insensitively, ignoring trailing spaces": login prompt ends in `login:`, `username:`, `user name:` or `user:`; password prompt ends in `password:` (also `passcode:`). Send the username + Enter once at the first login prompt, the password + Enter once at the next password prompt; password-only devices get the password at the first password prompt; "A login prompt with no username in the profile switches auto-login off." Off for the rest of the connection when the user types anything ("AI-dispatched keystrokes count too"), a device prompt appears (cursor line ends in `>`, `#` or `$`), the password has been sent, a second login prompt appears after the password, or no prompt within the timeout. "It never retries."
- Username but no saved password: "the password prompt box ... asks for it; Cancel leaves the user at the device's prompt to type by hand. The typed password is not saved unless the user ticks "Save password to this profile" in the box, and it is not kept for reconnects: a reconnect asks again."
- Status lines, verbatim text: `Connecting to host:port…`, `Connected to host:port (telnet — not encrypted)`, `Connection refused by host:port`, `Connection to host:port timed out`, `Could not resolve host`, `Connection closed by host:port`. "The connect timeout matches SSH's" (4 s per address, `ssh_connect()` in `src/term/ssh_session.c`). "A failed telnet connect is reported in the tab only; there is no "Connection Error" message box". "SSH-only timers (network-silence timeout, idle disconnect, keepalive) do not apply to telnet tabs."
- Password prompt box: "the profile name and host, one password field (with the reveal button), "Save password to this profile", OK and Cancel." SSH asks "from its connect thread ... through the `ConnUiKind` / `conn_prompt` ... machinery; telnet asks mid-session on the UI thread". "The buffer is wiped with `secure_zero()` after use." ## Decisions this plan makes (spec "Left to the builder" and readings)

1. **File layout:** core modules `telnet_proto`, `telnet_login`, `telnet_status`, `telnet_session`; socket glue in `src/ui/telnet_io.c` (Winsock, beside `local_pty.c`), not `src/config/` (which the native build compiles).
2. **Timing:** settle period `TN_LOGIN_SETTLE_MS = 300`; auto-login timeout `TN_LOGIN_TIMEOUT_MS = 20000`, counted from connect and restarted at each auto-send (so a slow device gets 20 s per step). Connect timeout 4000 ms per resolved address, as `ssh_connect()`.
3. **Status-line readings** (spec gap, listed in the report): the spec's `…` is the existing animated dots after `Connecting to host:port`; `Could not resolve host` carries the host name (`Could not resolve host <host>`) to honour Goal 4's "with host and port"; any other connect failure (unreachable network, no route) reads `Could not connect to host:port`, a line the spec does not list. An IPv6 literal prints as `[addr]:port`. Several addresses: the result reported is the best of them, connected > refused > timed out > other.
4. **Login matcher readings:** a second login prompt after the username was sent but before any password (a rejected username) switches auto-login off (never retries). The spec's "second login prompt after the password was sent" rule is already implied by "the password has been sent" switching it off. The matcher evaluates each settled burst of output once.
5. **The auto-sent username** is ordinary text: it gets local echo by the same rule as typed text. The password (profile or box) never does.
6. **Suppressed local echo is dropped, not deferred.** Local echo of control input: printable and UTF-8 bytes as typed, CR as CR LF, Backspace/DEL as `\b \b`, escape sequences and other controls not echoed.
7. **CR LF, not CR NUL**, for Enter; no device has been seen needing CR NUL.
8. **Saving a prompted password:** telnet saves on OK when the box is ticked (it cannot know whether the device accepted it); SSH saves only after authentication succeeds with it. Either way the password goes into the matching saved profile (kind, host, username, port) and `config_save()` encrypts it.
9. **SSH Cancel** at the password box ends the attempt with `Password entry cancelled.` in the tab and no "Connection Error" box (a user who cancelled needs no error dialog).
10. **No "not encrypted" tab glyph** beyond the status line (the spec's suggestion, not the maintainer's request).
11. **The AI system prompt** for a telnet tab is the SSH text with "an SSH terminal session" replaced by "a telnet terminal session" (remote-host wording, `[EXEC]` examples unchanged). Dispatch line clearing is the SSH mode (`READLINE`). Debug-log events for telnet use the existing `DLOG_SSH` category with `telnet.*` event names and thread tag `telnet`.
12. **End-to-end testing:** a native engine test drives a real `Terminal` through whole login flows (Task 5); a wintest loopback test drives the real socket backend against an in-process listener (Task 6); the integration harness gets a scripted PowerShell telnet responder and five cases (Task 12).

### Task 2: Telnet protocol core

**Files:**
- Create: `src/core/telnet_proto.h`, `src/core/telnet_proto.c`, `tests/test_telnet_proto.c`; modify `tests/runner.c`

**Interfaces:**
- Produces:
  ```c
  enum { TN_SE = 240, TN_SB = 250, TN_WILL = 251, TN_WONT = 252, TN_DO = 253, TN_DONT = 254, TN_IAC = 255 };
  enum { TN_OPT_ECHO = 1, TN_OPT_SGA = 3, TN_OPT_TTYPE = 24, TN_OPT_NAWS = 31 };
  enum { TN_TTYPE_IS = 0, TN_TTYPE_SEND = 1 };
  #define TN_REPLY_CAP(n) (4u * (size_t)(n) + 32u)   /* reply buffer that can never overflow for n input bytes */
  typedef struct {
      int state; unsigned char verb;               /* parser */
      unsigned char sb[32]; size_t sb_len; int sb_overflow;
      unsigned char us[256], him[256];             /* option enabled on our side / the server's side */
      int cols, rows;
      int cr_expanded;                             /* last encode ended in a CR we expanded */
  } TnProto;
  void   tn_proto_init(TnProto *p, int cols, int rows);
  /* Strip IAC from `in`; terminal bytes go to data (capacity >= len), answers to reply (capacity >= TN_REPLY_CAP(len)). */
  void   tn_proto_rx(TnProto *p, const unsigned char *in, size_t len,
                     unsigned char *data, size_t *data_len,
                     unsigned char *reply, size_t reply_cap, size_t *reply_len);
  /* Escape 0xFF and expand lone CR to CR LF; out capacity >= 2*len. Returns bytes written. */
  size_t tn_proto_encode(TnProto *p, const unsigned char *in, size_t len, unsigned char *out, size_t cap);
  /* Record the size; returns the NAWS subnegotiation to send (<= 13 bytes), 0 unless NAWS is agreed. */
  size_t tn_proto_resize(TnProto *p, int cols, int rows, unsigned char *out, size_t cap);
  int    tn_proto_server_echoes(const TnProto *p);   /* him[ECHO] */
  ```
  Answer table (passive; nothing is ever sent unprompted): `WILL ECHO`/`WILL SGA` with `him` off → set, reply `DO`; with `him` on → nothing. `WONT x` with `him[x]` on → clear, reply `DONT x`; off → nothing. `WILL` any other option → `DONT x`. `DO SGA`/`DO TTYPE` with `us` off → set, `WILL`; on → nothing. `DO NAWS` with `us` off → set, `WILL NAWS` then `IAC SB NAWS w1 w0 h1 h0 IAC SE` (each `0xFF` byte doubled, sizes clamped 0..65535); on → nothing. `DONT x` with `us[x]` on → clear, `WONT x`; off → nothing. `DO` any other option (`ECHO` included) → `WONT x`. `IAC SB TTYPE SEND IAC SE` with `us[TTYPE]` on → `IAC SB TTYPE IS 'X' 'T' 'E' 'R' 'M' IAC SE`. `IAC IAC` → one `0xFF` data byte; any other `IAC` command is dropped; subnegotiation longer than `sb` is consumed and ignored. Encoder: `0xFF` → `FF FF`; `CR LF` in the buffer passes as is; any other CR becomes `CR LF`; when the previous call ended with an expanded CR and this call starts with LF, that LF is dropped.
