# v1.3.3: terminal escapes and underline (PR #123)

**Status**: NOT RUN
**Needs**: a Linux host reachable by SSH (or use the local shell for the underline check); a way to change the Windows display scale (Settings > System > Display > Scale)
**Time**: 15 minutes

The tab stop, wrap and alternate screen changes are covered by the automated
tests. These checks look at the result on a real window. Run each command in a
Nutshell tab connected to the Linux host.

## Underline

1. **Underline is drawn at 100 %**
   Do: Set the Windows display scale to 100 %. Start Nutshell and connect to the Linux host. Run:
   ```
   printf '\033[4munderlined\033[0m plain\n'
   ```
   Expect: The word "underlined" has a thin line under it. The word "plain" has none. The line sits just below the letters and is not touching the next row.
   If it fails: Screenshot. Note the font name and size from Settings.
   Result:

2. **Underline at 150 %**
   Do: Set the display scale to 150 %. Sign out and in if Windows asks. Start Nutshell again and run the same command as check 1.
   Expect: The line is still under the word, and is thicker than at 100 %, not a hairline and not a heavy bar.
   If it fails: Screenshot at 150 %. Note whether the line is too close to the text, too far, or missing.
   Result:

3. **Underline with a missing glyph**
   Do: Run:
   ```
   printf '\033[4mabc \xf0\x9f\x98\x80 def\033[0m\n'
   ```
   Expect: "abc" and "def" are underlined with one unbroken line. The character in the middle shows as the font's fallback shape or a box. It must not be a solid block of colour covering the text.
   If it fails: Screenshot. Say whether a solid coloured block appeared.
   Result:

4. **Underline with bold and reverse video**
   Do: Run:
   ```
   printf '\033[1;4mbold underlined\033[0m  \033[7;4mreverse underlined\033[0m\n'
   ```
   Expect: Both phrases have an underline. The bold one is bold. The reverse one has swapped colours and its line is visible against the filled background.
   If it fails: Screenshot.
   Result:

## Tab stops

5. **Tab and back tab on the default stops**
   Do: Run:
   ```
   printf 'a\t\tb\033[Zc\n'
   ```
   Expect: The letter "a" is at column 1. The letter "c" is at column 17 and no "b" is visible, because back tab returned to column 17 and "c" wrote over it.
   If it fails: Note where "b" and "c" ended up (count columns).
   Result:

6. **Forward tab (`CSI I`)**
   Do: Run:
   ```
   printf 'a\033[2Ib\n'
   ```
   Expect: "b" appears at column 17, two tab stops after "a".
   If it fails: Note the column of "b".
   Result:

7. **Set and clear tab stops**
   Do: Run:
   ```
   printf '\033[3g\r\033[9C\033H\033[10C\033H\r\tX\tY\n'
   ```
   Expect: "X" is at column 10 and "Y" is at column 20. Then open a new tab for the next checks, because the stops stay changed in this one.
   If it fails: Note the columns of X and Y.
   Result:

## Scroll region and alternate screen

8. **Wrap inside a scroll region**
   Do: In a new tab, run:
   ```
   clear; printf 'TOP1\nTOP2\nTOP3\nTOP4\n'; printf '\033[5;10r\033[10;1H'; seq -s ' ' 1 200; printf '\033[r\033[14;1H'
   ```
   Expect: TOP1 to TOP4 stay on rows 1 to 4. The long line of numbers wrapped and scrolled only in rows 5 to 10. The top rows were not pushed up.
   If it fails: Screenshot. Say whether TOP1 scrolled away.
   Result:

9. **Leaving a full-screen program keeps the region**
   Do: In a new tab, run `clear; printf '\033[5;10r\033[10;1H'`, then `less /etc/passwd`, press `q`, then run `seq 1 30`.
   Expect: After `q` the shell is back. The numbers scroll only inside rows 5 to 10, as the shell asked before `less`. Run `printf '\033[r'` and `clear` afterwards to reset.
   If it fails: Screenshot. Say whether the numbers scrolled the whole screen.
   Result:

10. **Resize on the alternate screen**
    Do: In a new tab, run `less /etc/passwd`. Drag the window edge to make it clearly taller and narrower. Press `q`. Run `seq 1 200`. Scroll back with the mouse wheel.
    Expect: After `q` the shell is back with no leftover text from `less`. The numbers print normally, and the wheel scrolls back through earlier lines (scrollback works).
    If it fails: Screenshot. Say whether scrollback was empty or the screen scrolled oddly.
    Result:

11. **vim and less still look right**
    Do: In a new tab, open `vim /etc/passwd`. Scroll down with Page Down, then quit with `:q`. Then run `man ls` and quit with `q`.
    Expect: Both draw correctly, scroll correctly and leave the shell prompt on a clean screen.
    If it fails: Screenshot of the broken state.
