# v1.3.4: session I/O (PR #126)

**Status**: NOT RUN
**Needs**: a Linux host reachable by SSH; a telnet host (optional, for check 8); a way to switch the network off (Wi-Fi) for check 9; Task Manager
**Time**: 25 minutes

The automated tests cover the resize, paste chunking, logging and repaint
logic. These checks look at the result on a real window and a real network.

## SSH size after connecting

1. **Resize while connecting**
   Do: Start an SSH connection to the Linux host. While it is still connecting, resize the window (drag a corner, or maximise). When the prompt appears, run:
   ```
   stty size
   ```
   Expect: The rows and columns match the window. Compare with `tput lines; tput cols` after one more resize, or with the size shown while dragging. You did not have to nudge the window.
   If it fails: Note the window size, the `stty size` output, and whether nudging the window fixes it.
   Result:

2. **A full-screen program fills the window**
   Do: Repeat check 1, then start `tmux` or `vim`.
   Expect: The program fills the whole window, with no empty band at the bottom or right.
   If it fails: Screenshot. Note the program and the window size.
   Result:

## Paste

3. **A long paste arrives complete**
   Do: Over SSH run `cat > /tmp/paste-test.txt`. Paste about 200 lines of plain text. Press Ctrl+D. Run:
   ```
   wc -l /tmp/paste-test.txt; head -n 2 /tmp/paste-test.txt; tail -n 2 /tmp/paste-test.txt
   ```
   Expect: The line count matches what you pasted. The first and last lines match the source. No lines are glued together or out of order.
   If it fails: Note the count you expected and the count you got, and where the text goes wrong.
   Result:

4. **Paste into vim**
   Do: Over SSH start `vim`, press `i`, and paste the same text.
   Expect: It arrives as typed text. There is no auto-indent staircase and no stray `~` characters.
   If it fails: Screenshot the vim window.
   Result:

5. **Accents and emoji**
   Do: Paste a few lines with accented letters (for example "café, naïve, Zürich") and an emoji into `cat > /tmp/paste-test2.txt`, press Ctrl+D, then run `cat /tmp/paste-test2.txt`.
   Expect: The text comes back unchanged.
   If it fails: Note which characters changed and what they became.
   Result:

6. **Paste with a delay**
   Do: In Settings > Terminal set "Paste Delay (ms):" to a value such as 100. Over SSH run `cat > /tmp/paste-test3.txt`, paste 20 lines, press Ctrl+D, and run `wc -l /tmp/paste-test3.txt`.
   Expect: The lines arrive one at a time, and all 20 are there at the end.
   If it fails: Note the delay value and the line count.
   Result:

7. **Paste into a local shell**
   Do: Open a local PowerShell tab. Paste 5 lines that each print a word, for example `echo one`, `echo two`, and so on.
   Expect: Each line is entered and its word is printed.
   If it fails: Note what happened to the lines.
   Result:

8. **Paste over telnet (optional)**
   Do: If a telnet host is at hand, connect to it and paste 200 lines.
   Expect: All of it arrives, or a notice says the paste stopped and how many bytes were sent.
   If it fails: Note how much arrived and whether any notice appeared.
   Result:

## A paste that stops

9. **Network lost during a paste**
   Do: With "Paste Delay (ms):" set to 100, start a 200-line paste over SSH. Part way through, switch Wi-Fi off. Wait for the session to drop. Switch Wi-Fi back on.
   Expect: One notice titled "Paste Stopped" that says how many bytes were sent. No second notice. No further lines arrive after the network returns.
   If it fails: Note the exact text of the notice, how many notices appeared, and whether lines arrived later.
   Result:

## Start Logging

10. **A log folder that does not exist yet**
    Do: In Settings > Logging set "Log Directory:" to a new folder whose parent exists, for example `C:\Users\Public\nutshell-logs-new`. Connect to a session and choose File > Start Logging. Type a few commands.
    Expect: The folder is created. The tab shows the logging mark. The log file holds the session's output.
    If it fails: Note the path, whether the folder exists, and any notice.
    Result:

11. **A log folder that cannot be written**
    Do: Set "Log Directory:" to `C:\Windows\System32\nutshell-logs`. Choose File > Start Logging.
    Expect: A notice says the log could not be started, with the path and the reason. The tab does not show the logging mark.
    If it fails: Note the notice text, or that none appeared, and whether the mark showed.
    Result:

## Background tabs

12. **A busy background tab stays quiet**
    Do: Open two SSH tabs. In the first run something that prints forever, for example `while true; do date; sleep 1; done`. Switch to the second tab and leave it idle for a minute with Task Manager open.
    Expect: Nutshell's CPU use stays low and steady.
    If it fails: Note the CPU percentage and whether it climbs.
    Result:

13. **Back to the busy tab**
    Do: Switch back to the first tab.
    Expect: The screen is complete and current, with no stale or blank rows.
    If it fails: Screenshot.
    Result:

14. **An editor in the second tab**
    Do: In the second tab run `nano` or `vim` while the first tab keeps printing. Type in the editor.
    Expect: The typing redraws promptly.
    If it fails: Note the editor and how long the redraw takes.
