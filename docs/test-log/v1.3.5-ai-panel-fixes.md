# v1.3.5: AI panel fixes (PR pending)

**Needs**: an AI provider with a working key and AI Assistant switched on; an SSH session to a Linux host; optionally a Cisco NX-OS or ASA session for checks 8 and 9

The automated tests cover the cursor choice, the stop handling and the command
tables. These checks look at the result in a real window.

## The pointer

1. **The I-beam over text**
   Do: Open the AI panel with a conversation that has a reply, a message of your own, a bulleted list and a code block. Move the pointer over reply text, your own bubble, a bullet and a code line. Then move it over a command row, a tickbox, a chip, Retry, a copy icon and the Thinking header. Then move it over the margins.
   Expect: Over the four kinds of text the pointer is an I-beam. Over the command row, tickbox, chip, Retry, copy icon and Thinking header it stays the hand. Over the margins it is the arrow.
   If it fails: Note which place shows the wrong pointer, the theme and the zoom level.

## Stopping a reply

3. **Stop with some text shown**
   Do: Ask the AI a long question, for example for a detailed essay. When text has appeared, press Stop once.
   Expect: The part of the reply that arrived stays, followed by `[cancelled]`.
   If it fails: Screenshot. Note whether the text vanished or `[cancelled]` is missing.
   Result:

4. **Stop before any text**
   Do: Ask a question and press Stop before any text shows.
   Expect: Only `[cancelled]` is shown.
   If it fails: Screenshot.
   Result:

5. **The chat survives a tab switch**
   Do: After check 3 or 4, switch to another tab and back.
   Expect: The chat looks the same as before. The text `[reply stopped by the user]` appears nowhere in it.
   If it fails: Screenshot both views.
   Result:

6. **No command runs after Stop**
   Do: Ask for something that makes the AI write a command block. Press Stop just after the finished command block has appeared. Switch to another tab and back.
   Expect: No command card appears and nothing runs in the terminal.
   If it fails: Note what ran and when you pressed Stop. Press Ctrl+C in the terminal if something runs.

7. **A reply after Stop**
   Do: After a Stop, send another message.
   Expect: The AI gives a normal reply.
   If it fails: Note the error text, if any.

## Command classification

8. **do CMD on NX-OS and ASA**
   Do: On a Cisco NX-OS or ASA session, in configuration mode, ask the AI to run `do show version`. Then ask it to run `do reload`. Only read what each approval card says. Do not approve `do reload`; press Deny.
   Expect: `do show version` is treated as a read-only command. `do reload` is treated as critical and asks for approval.
   If it fails: Screenshot the card and note the platform.

   Expect: The reason is a full phrase. It never ends in a bare colon.
