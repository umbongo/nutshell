# v1.3.1: AI speech for conversations, Mistral and Custom (PR #120)

**Status**: NOT RUN
**Needs**: a microphone; headphones and laptop speakers; a Mistral key (`<your Mistral key>`); a Kokoro-FastAPI or other OpenAI-compatible `/audio/speech` server on your network (for the Custom checks); a second speech key to test separate keys; a way to cut Wi-Fi; an SSH host
**Time**: 60 minutes

AI speech reads a conversation's replies with a text-to-speech provider
instead of Windows speech. Do the Mistral checks first. Mistral's stream
parser was merged without a real capture of its output, so these checks are
the first real test of it.

Set up: Settings > Voice. Enable voice on, Mode Conversation, Speech set to
AI speech, Speech provider Mistral, Speech API key `<your Mistral key>`, Save.

## Mistral first

1. **The first reply, to see if the stream parser works**
   Do: Press Right Shift in the AI panel and say "Say hello in one sentence". Wait for the reply.
   Expect: The reply is spoken in a Mistral voice.
   If it fails: If the chat shows "AI speech is off for this conversation: unsupported audio format", report that exact message. It means Mistral sent raw PCM rather than WAV and the fix is the `pcm` path. Copy any other message exactly too.
   Result:

2. **Voice and accent**
   Do: With the default voice (`voice_1787`) and then another English (UK) voice from the AI voice list, ask for a longer reply.
   Expect: A British accent. The first word starts within a second or two. No gaps or clicks between chunks. Another app's audio ducks during the reply.
   If it fails: Note the voice name, the delay in seconds and where a gap or click happened.
   Result:

3. **Stop latency**
   Do: During a long reply press Escape or the voice key.
   Expect: The speech stops within about half a second.
   If it fails: Note the delay.
   Result:

4. **Carry on after a cut-in**
   Do: During a long reply cut in with your voice, then say "carry on".
   Expect: The reply resumes from where it stopped, in AI speech.
   If it fails: Note what you heard.
   Result:

5. **Cost on Mistral's page**
   Do: After a few replies open Mistral's usage page in a browser.
   Expect: The use shows up and the cost looks sensible for the text spoken.
   If it fails: Note the figures.
   Result:

## Play sample

6. **Play sample with unsaved values**
   Do: In Settings > Voice change the voice or model without saving. Press Play sample.
   Expect: The sample uses the values on screen, not the saved ones.
   If it fails: Note which voice you heard.
   Result:

7. **A failed sample says why**
   Do: Type a wrong key in the Speech API key box. Press Play sample.
   Expect: A note under the meter: "Could not play the sample: the speech provider refused the key (HTTP 401)".
   If it fails: Note the exact text.
   Result:

## Custom server

8. **Kokoro with `bf_emma`**
   Do: Speech provider Custom. Speech base URL `http://<your Kokoro host>:8880/v1`. Leave the key empty. AI voice `bf_emma`. Save. Have a conversation.
   Expect: The reply is spoken in that voice. A line warns "Not encrypted: your API key and each spoken reply's text cross the network in plain text." because the URL is http.
   If it fails: Note the message and the URL form you used.
   Result:

9. **Custom with a key**
   Do: Type a key on the Custom server's Speech API key row and run a conversation.
   Expect: It works. Wrong key shows the refusal note.
   If it fails: Note the message.
   Result:

10. **Unsupported sample rate**
    Do: If you can run a server that returns 22,050 Hz audio, point at it and talk.
    Expect: A note once per conversation says why AI speech is off and the reply is spoken with Windows speech. Skip if you have no such server.
    If it fails: Note the note text.
    Result:

## Keys

11. **Shared, separate and rebound keys**
    Do: Use the speech-to-text key for speech (leave the Speech API key empty) and see if it works. Then give a separate key. Then switch provider Mistral to Custom and back, and reopen Settings.
    Expect: A typed key is tied to the provider it was typed for and does not show under another one. Switching back shows it again. After Save and restart it still works.
    If it fails: Note which key went missing.
    Result:

12. **A long Custom URL and key**
    Do: Save Settings with a Custom speech URL of about 248 characters and a long key.
    Expect: The save works. (If it does not, the whole save fails.)
    If it fails: Note the message.
    Result:

13. **A refused Custom URL**
    Do: Type a Custom base URL with a user name in it (`http://user@host/v1`), then with a `?` in it.
    Expect: The URL with a user name is refused. (A `?` is a known issue: note what happens.)
    If it fails: Note the message.
    Result:

## Fallbacks and failures

14. **Wi-Fi pulled mid-reply**
    Do: Start a long reply. Switch Wi-Fi off a few seconds in.
    Expect: The rest of the reply is read by Windows speech, with one note "AI speech failed: using Windows speech". One note per conversation.
    If it fails: Note what you heard and saw.
    Result:

15. **Wrong key and wrong model**
    Do: Put a wrong Mistral key, run a conversation. Then the right key and a wrong model name.
    Expect: One note each time saying AI speech is off for the conversation with a reason. The reply is read by Windows speech. It does not retry on each reply.
    If it fails: Note the note text.
    Result:

16. **A hung upload**
    Do: Start a conversation, speak, and make the network drop right after you stop talking so the speech-to-text upload hangs.
    Expect: The conversation ends at its deadline (the notes give 130 s for hearing and 180 s for ending) rather than staying in "Working" or "Sending".
    If it fails: Note how long it hung and the header text.
    Result:

17. **Redirects are refused**
    Do: For each built-in speech-to-text provider you have a key for, record once.
    Expect: It works. If a provider redirects you see "Redirect refused (HTTP n)".
    If it fails: Note the provider and the code.
    Result:
